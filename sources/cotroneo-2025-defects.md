## Design & method

**Type:** large-scale controlled-generation comparison (lab-style, not field). Paired design: the *same* natural-language specification (docstring + function signature) yields one human implementation and three LLM implementations, so counts are directly comparable across authors within each language.

- **Human baseline:** functions mined from public GitHub via CodeSearchNet (through the HMCorp dataset of Xu et al., TOSEM 2025). 285,249 Python functions from 12,632 repositories and 221,795 Java functions from 4,296 repositories (16,928 unique repos total). These are real functions from real (largely pre-2019, CodeSearchNet-era) open-source projects, written *in context* — then analysed as isolated snippets.
- **AI code, three models:**
  1. **ChatGPT** = `gpt-3.5-turbo`, April 2023 generation (inherited from HMCorp);
  2. **DeepSeek-Coder-Instruct 33B** (quantised), generated by the authors;
  3. **Qwen2.5-Coder-Instruct 32B** (quantised), generated by the authors.
  Prompts = original docstring + function signature, default model settings and each vendor's preferred prompt format; single-shot generation, no iteration, no execution feedback. Post-generation cleanup (indentation normalisation, stripping of non-code text, syntactic parse checks) refined via manual inspection rounds.
- **Final dataset:** 507,044 ⟨docstring, human, ChatGPT, DSC, Qwen⟩ tuples (285,249 Python + 221,795 Java) — >2M code samples analysed in total across the four authors.
- **Defect classification:** Pylint for Python (350 of 417 rules after excluding style/naming/docs) and PMD for Java (226 of 290 rules after excluding style, documentation, the 2-rule security set, and 12 class-design rules triggered by the dummy-class wrapping PMD requires). All rules manually mapped to ODC (Chillarege et al. 1992) **Defect Type** categories (Assignment, Algorithm, Interface, Checking, Timing, Function/Class/Object) by two authors independently with consensus resolution; Documentation and Build/Package/Merge types excluded as inapplicable to isolated snippets. Classification is done by the static tools + this mapping — no human labelling of individual defects.
- **Vulnerability detection:** Semgrep OSS with all security-focused Python/Java rules available as of April 2025 (OWASP Top 10 / CWE Top 25 -aligned rulesets), mapped to CWE identifiers with severity levels.
- **Complexity:** lizard (NLOC, cyclomatic complexity) + tiktoken (token counts, unique tokens); function-name length by character count.
- **Statistical testing: none.** No hypothesis tests, no confidence intervals, no effect-size statistics anywhere in the paper. All comparisons are descriptive counts/means over very large N. The paired same-N design makes raw counts comparable, but words like "significantly" in the text are informal, not inferential.

## Findings (extraction records, §4 schema)

Common fields: `source_id` cotroneo-2025-defects | `year` 2025 | `tier` B | `era` E2 | `method` controlled paired generation + static analysis | `population` 507,044 paired specs; human code from 16,928 GitHub repos; models gpt-3.5-turbo (Apr 2023), DeepSeek-Coder-33B, Qwen2.5-Coder-32B | `task_types` T3 (isolated function generation; human comparator drawn from mature codebases) | `measurement_basis` measured (static analysis) | `cost_data` none | `seniority_split` none | `independence_flags` academic, EU/MUR public funding, no vendor COI | `relevance_to_us` 3.

**F1 — Python defect rates: AI mixed, ChatGPT cleanest (Table III).** Defective samples (≥1 issue) out of 285,249: human 158,221 (55.47%); ChatGPT 110,528 (38.75%); DeepSeek 173,899 (60.96%); Qwen 178,225 (62.48%). Total defect counts: human 429,247; ChatGPT 185,110; DSC 319,643; Qwen 574,916. Direction: mixed — ChatGPT better than human, DSC/Qwen worse.

**F2 — The human Python defect count is dominated by one contextual rule.** 47% of human Python defects (202,259 of 429,247) are a single Pylint rule, `protected-access` — accessing `_underscore` members, common and often intentional in real OO codebases and partly an artefact of analysing in-context functions as isolated snippets. Excluding it, human total defects drop to ~227k, comparable to ChatGPT. Methodologically important: headline "human code has more defects" claims from static analysis can hinge on convention rules that penalise mature-codebase style.

**F3 — Java defect rates: humans beat two of three models; aggregate direction reverses by language.** Defective samples out of 221,795: human 76,049 (34.29%); ChatGPT 78,241 (35.28%); DeepSeek 155,077 (69.92%); Qwen 60,389 (27.23%). Total defects: human 202,129; ChatGPT 161,056; DSC 242,437; Qwen 123,180. Paper's aggregate: vs the human baseline, AI models average **−4k defective samples in Python but +22k in Java**. Model heterogeneity is large: Qwen is worst in Python and best in Java; DSC is worst in Java by a wide margin.

**F4 — Distinct defect-type profiles (ODC).** Human code skews to Interface (Python: `protected-access` >250k-driven) and Algorithm/complexity defects (Java: >96k algorithm-type; top rules CyclomaticComplexity 15,435, AvoidInstantiatingObjectsInLoops 14,351, CognitiveComplexity 13,065, AvoidCatchingGenericException 9,749) — maintainability/design-debt signatures of mature codebases. AI code skews to Assignment and unused-construct defects: ChatGPT Python `unused-argument` 32,992, `unused-variable` 14,408, `unspecified-encoding` 14,312; DSC Python `unused-argument` 111,703, `too-few-public-methods` 64,279; Qwen Python `unused-argument` 213,264, `redefined-outer-name` 57,252. Java AI code overuses hardcoded debugging: `SystemPrintln` (DSC 37,986; Qwen 13,329; ChatGPT 10,428), `ImmutableField` (DSC 41,669), unused fields/parameters. Authors' reading: AI replicates parameter patterns from signatures without using them; produces "syntactically plausible but structurally shallow" code.

**F5 — Generation-failure (incorrect-sample) rates.** Syntactically invalid or empty outputs: Python — human 3,712 (1.30%), ChatGPT 2,549 (0.89%), DSC 20,783 (7.29%, incl. 19,612 empty), Qwen 7,190 (2.52%). Java — human 245 (0.11%), ChatGPT 2,056 (0.93%), DSC 34,382 (15.50%, incl. 19,071 empty), Qwen 3,833 (1.73%, incl. 3,209 empty). DSC's failures reduce its analysable surface, flattering its defect counts.

**F6 — Python security: AI more vulnerable in volume, not breadth (Table IV).** Vulnerable samples: human 15,835 (5.55%); ChatGPT 22,864 (8.02%); DSC 22,878 (8.02%); Qwen 16,316 (5.72%). Total CWE-mapped issues: human 25,678; ChatGPT 40,035; DSC 39,982; Qwen 34,250. Unique CWEs nearly identical (human/ChatGPT/Qwen 45, DSC 43) — AI repeats the *same* flaw types more often rather than triggering new ones. Density per vulnerable sample: human 1.62, ChatGPT/DSC 1.75, Qwen 2.10.

**F7 — Java security: the largest human-vs-AI gap in the study.** Vulnerable samples: human 6,660 (3.00%); ChatGPT 18,144 (8.18%); DSC 43,386 (19.56%); Qwen 13,620 (6.14%). Total issues: human 11,677; ChatGPT 29,807; DSC 76,678; Qwen 21,301. Unique CWEs: human 42; ChatGPT 49; DSC 51; Qwen 41. Paper's aggregate: AI averages **+5k vulnerable samples in Python and +18k in Java** vs human. Human code is the most secure author on every security metric in both languages.

**F8 — CWE profiles diverge; AI skews to high-risk (CWE Top 25) categories.** Python: CWE-78 OS Command Injection — human 2,243 vs ChatGPT 13,419, DSC 10,908, Qwen 7,318; CWE-400 Uncontrolled Resource Consumption — human 1,631 vs 6,887/7,987/4,857; CWE-611 XXE — human 0 vs 4,587/6,372/3,521. Human Python instead skews to CWE-754 Improper Check for Exceptional Conditions (13,157 vs ChatGPT 1,539, DSC 0, Qwen 8,214). Java: CWE-532 Log Information Exposure — human 3,736 vs DSC 30,031 (ChatGPT 6,915, Qwen 9,271); CWE-489 Active Debug Code — human 1,948 vs DSC 17,533; CWE-798 Hardcoded Credentials — human 784 vs DSC 5,199; CWE-22 Path Traversal — human 0 vs ChatGPT 2,886, DSC 3,738. Some failure modes are model-specific (CWE-319 Cleartext Transmission: DSC only, 1,928 Python instances).

**F9 — Complexity: AI code is consistently shorter, simpler, and lexically narrower (Table V).** Python averages (human / ChatGPT / DSC / Qwen): NLOC 12.72 / 6.89 / 5.16 / 4.47; CCN 3.97 / 2.47 / 2.00 / 1.84; tokens 142.45 / 79.33 / 68.37 / 58.68; unique tokens (corpus) 70,542 / 62,717 / 60,199 / 63,265. Java: NLOC 13.38 / 8.42 / 6.70 / 6.14; CCN 3.48 / 2.35 / 1.83 / 1.90; tokens 119.66 / 76.51 / 59.60 / 61.43; unique tokens 57,356 / 52,540 / 47,737 / 50,698. Paper's aggregates: AI code averages **−6.75 NLOC, −1.66 CCN, −63.74 tokens, −7,756 unique tokens** vs human. Direction is ambiguous for quality: simpler code may be more readable, but the authors flag risks of under-specification, thin edge-case handling, and shallow logic.

**F10 — Similarities (recorded with equal diligence).** (a) ChatGPT's Java defective-sample rate is near-identical to human (35.28% vs 34.29%). (b) Unique-CWE breadth in Python is essentially equal across all four authors (43–45). (c) Excluding the `protected-access` artefact, human and ChatGPT Python total defect counts are comparable (~227k vs 185k). (d) Function-name lengths are broadly comparable in Python (human 14.16 vs Qwen 13.95, DSC 12.51; ChatGPT longer at 17.56); in Java, AI names run notably longer (DSC 19.32, ChatGPT 18.92 vs human 13.98).

## Which differences are statistically tested

None. The study reports raw counts, percentages, and means over a paired ~500k-spec design with no inferential statistics. At this N most reported gaps would trivially pass a significance test, but no test, CI, or effect-size measure is actually computed, and no correction is made for the analytical asymmetries noted below. Treat every comparison as descriptive.

## Grading

- **Tier: B** — peer-reviewed (ISSRE), very large N, paired design, transparent replication package; but lab-style static analysis with no counterfactual deployment outcome, no inferential statistics, and material construct-validity caveats. Carries claims with caveats.
- **Era: E2** (per §2, by modality). Single-shot docstring-to-function generation via chat-model APIs — no agentic loop, no IDE integration, no iteration or verification step. The ChatGPT arm is `gpt-3.5-turbo` from **April 2023**, two model generations behind 2025 frontier tools; DSC-33B and Qwen2.5-32B are 2024-era open-weight models run quantised. Nothing here measures E3 agentic workflows. Under the era-transfer rule, usable as baseline/methodology/plausibly era-independent evidence only; must carry a "pre-agentic" label if any figure reaches the exec brief.
- **Independence:** academic authors, University of Naples Federico II; funded by EU Next Generation EU / Italian MUR grants (IDA project PE00000014; SERENA-IIoT, PRIN 2022 2022CN4EBH). No vendor funding, no COI flag.
- **One-line verdict:** *Can* support: descriptive, pre-agentic evidence that single-shot LLM-generated code has a systematically different defect/vulnerability profile from human code (more unused constructs, debug leftovers, and repeated high-risk CWEs; less structural complexity), with strong model and language heterogeneity. *Cannot* support: any claim about agentic tools, AI-assisted (human-in-the-loop) code as merged in real projects, defect rates in production, functional correctness, or velocity/cost effects.

## Generalisability limits

1. **Controlled generation, not in-the-wild code.** LLM outputs are raw single-shot completions with no human review, editing, iteration, tests, or CI — i.e. the artefact studied is "what the model emits", not "AI-assisted code as shipped". Real-world AI-assisted defect rates could be far lower (review filters issues) or differently distributed (agents iterate against tests). Symmetrically, the human code *did* pass real project processes, so this is not a like-for-like process comparison — it compares finished human code against unfiltered model output.
2. **Context asymmetry penalises the human baseline too.** Human functions were written inside full repositories, then analysed as isolated snippets; rules like `protected-access` (47% of human Python defects) largely reflect stripped context, and Java functions needed dummy-class wrapping for PMD. The authors mitigate but cannot remove this.
3. **Dated human corpus and models.** Human code comes from CodeSearchNet-era (~pre-2019) GitHub; the ChatGPT arm is April 2023 gpt-3.5-turbo. Both sides of the comparison predate 2025 practice; frontier 2025 models and agentic modes are unstudied.
4. **Static analysis only.** No execution, no test oracles — semantic correctness against the docstring is never checked, so "fewer defects" ≠ "more correct". Semgrep is syntactic pattern-matching and will yield false positives, plausibly asymmetrically (e.g. AI's fondness for `subprocess`/string-built commands inflates CWE-78 hits regardless of exploitability in context).
5. **Snippet granularity.** Function-level snippets only; says nothing about multi-file, architectural, or integration-level quality — the level where agentic tools operate.
6. **Two languages, three models, one prompting style** (docstring + signature); the authors themselves list this under external validity.

## Cross-cutting tags & relevance

- Task type T3 (isolated function generation); the human comparator embodies T4-like mature-codebase style, which is itself the source of a key confound — worth remembering wherever this study is cited against brownfield claims.
- Feeds: RQ1 (quality dimension of the value map, pre-agentic), RQ3 (failure-mode characterisation: unused constructs, debug leftovers, high-risk CWE repetition), RQ4 (quality-debt side of cost, weakly), RQ2/RQ6 (methodology: how tool-rule choice — one Pylint rule = 47% of a headline count — can drive static-analysis conclusions; anti-metric caution for "defect counts from linters").
