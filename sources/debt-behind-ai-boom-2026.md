## What this document is
A mining-software-repositories study of AI-attributed commits in public GitHub repositories (at least 100 stars; Python, JavaScript, TypeScript production files only). For each commit it runs static analysis on the file before and after the change, attributes newly appearing issues on changed lines to the commit, and then checks whether each issue is still present at the repository HEAD (as of roughly Feb-Mar 2026). Three RQs: types of debt introduced (RQ1), comparison across five assistants (RQ2), persistence (RQ3).

**There is no human-commit baseline, no defect or incident outcome, no productivity outcome. Every outcome is a static-analysis finding.** It is a descriptive study of AI-attributed code, not a comparison of AI against anything.

## Full notes

### 1. Attribution method and dataset
- **Discovery:** GH Archive PushEvents (via BigQuery), Jan 2024 to Oct 2025; fields matched: actor login, author name, author email, commit message. Plus GitHub REST API sweep of top-starred repositories. 587,118 candidate repos; 12,770 after the 100-star filter; 6,699 after full-history bare-clone scan and language filter (29 AI tools left traces).
- **Attribution rules (explicit Git metadata only):** (1) actor logins (e.g. `copilot-swe-agent[bot]`), (2) author emails (e.g. `noreply@anthropic.com`), (3) author names (e.g. "Cursor Agent"), (4) `Co-authored-by` trailers. Rules reviewed manually by two authors. Full rule list only in the replication package, so the exact trailer/marker strings were not verified here. Commits with no trace are invisible. The authors liken this to self-admitted technical debt research: a "visible, attributable subset".
- **Which assistants (the paper's five; threshold more than 10,000 attributed commits):** GitHub Copilot, Claude (all variants, including Claude Code), Cursor, Gemini, Devin. **Not** Codex, Aider or Windsurf (below the threshold or grouped into the 29 excluded tools). Note the paper's own intro says "Claude" not "Claude Code"; the grouping lumps all Claude-attributed commits.
- **Table I (analysed set, 302,579 commits, 6,299 repos; repos may use several tools):**

| Tool | Commits | Share | Repos | Commits/repo |
|---|---|---|---|---|
| Claude | 138,249 | 45.7% | 2,434 | 56.8 |
| GitHub Copilot | 118,012 | 39.0% | 4,487 | 26.3 |
| Cursor | 19,587 | 6.5% | 714 | 27.4 |
| Devin | 14,302 | 4.7% | 298 | 48.0 |
| Gemini | 12,429 | 4.1% | 681 | 18.3 |

  (Shares are my arithmetic from Table I.) Pre-exclusion set was 317.4K commits in 6,412 repos; exclusions were unavailable repos, deletion-only commits, and commits touching no production Py/JS/TS file. Monthly commit volume rises sharply from mid-2025 (Fig. 6a).
- **Overlap with AIDev (Li et al. 2025) or other corpora: none stated.** The paper never mentions AIDev. The dataset is self-built from GH Archive plus API scanning. AIDev covers PRs from five agents (Codex, Devin, Copilot, Cursor, Claude Code) in 100+-star repos; overlapping *repositories and commits* are plausible given both mine star-filtered public repos for agent traces, but the paper does not test for it. Verdict: independently constructed corpus, overlap unquantified.
- **Attribution validation:** 100 random commits manually checked by two authors; 99 verifiable, all 99 correct (precision 99.0% conservative, 100% of verifiable). This checks that the *trace is genuine*, not that the AI *wrote the changed lines* (commits may mix human and AI edits; acknowledged in threats).

### 2. Design
- **Tools:** ESLint (JS/TS) and Pylint (Python) for code smells and correctness issues; Semgrep for security. (No SonarQube or CodeQL.) Issue records: rule ID, line, detector, message.
- **Per-commit differential:** parent-version vs commit-version of each modified production source file. Issue "introduced" = present after, unmatched before (same rule+message at same or nearby line), and on a line inside the git-diff changed lines. Issue "fixed" = in before-set, absent after. Tests, docs, config, build artefacts, vendored files excluded by path/name patterns.
- **Survival:** each introduced issue checked at HEAD (file followed through renames with `git log --follow`; matched by rule ID plus surrounding code context). Surviving = same issue still present. Deleted or rewritten file = counted as not surviving (so survival is likely slightly underestimated, per authors).
- **Human baseline: ABSENT.** Explicit statement in Threats to Validity: they "do not compare AI-authored commits against a baseline of purely human-written commits", arguing a reliable human-only baseline is hard because unlabelled AI use and mixed commits would contaminate it. Consequently no figure in this paper says AI code is worse or better than human code. The authors' own Section II-C/VII cite prior work on human smell persistence (Tufano et al.; Digkas et al.) that suggests smells also linger in human code, but no numbers are compared.
- **Pipeline validation (100 issues, 99 labelled):** issue validity: raw agreement 0.960, kappa 0.851; against adjudicated labels accuracy 85.9%, precision 85.9% (about 14% of reported issues are false positives), recall 100%, F1 92.4%. Survival classification: agreement 0.980, kappa 0.960; accuracy 84.8%, precision 86.7%, recall 81.2%, F1 83.9%. Small samples (n=99 each), so about 15% error on survival labels is itself non-trivial.

### 3. Numbers (v2)
- **484,366 introduced issues** in 3,946 repos (62.6% of 6,299) and **27,677 commits (9.1% of 302,579)**.
- **Composition (Table II):** code smells 432,748 (89.3%; 3,812 repos; 25,740 commits); correctness issues 28,931 (6.0%; 665 repos; 1,650 commits); security issues 22,687 (4.7%; 1,643 repos; 5,142 commits).
- **Top rules (Table III):** smells: broad exception handling 41,374 (8.5% of all issues), unused variables/parameters 28,272, unused argument 24,357, shadowed outer variable 20,647, access to protected member 19,796. Correctness: undefined variable/reference 23,856 (82% of correctness issues by my arithmetic), redeclared symbol 1,888. Security: path traversal via path.join/resolve 8,677 (38% of security issues), unsafe format string 4,792, non-literal regex 1,212, child process execution 607.
- **Severity: not reported.** No severity grading by tool-rated level; the paper only asserts correctness/security matter more than smells. Security findings include "latent unsafe patterns" and the authors say they do not separate exploitable from latent. Exploitable vulnerability count: unknown.
- **Language (Table IV):** Python top rules: broad exception 14.9% of Python issues, unused argument 8.8%, undefined variable 8.6%. JS/TS: unused variables 13.6%, shadowed variable 8.9%. No per-language issue-introduction rate; only rule shares. The claim "smells dominate in both languages" is asserted.
- **Per-assistant introduction rate (Fig. 7, from text only; figure data not in HTML text):** share of commits with at least one issue ranges from **17.4% (Copilot) to 29.1% (Gemini)**; "more than 15%" for every tool. Per-tool values for Claude, Cursor, Devin not given in text. Table V (issues per commit) not extractable from text; text says Claude highest at 1.95 and Devin lowest at 0.89. The authors caution differences "may be due to usage patterns and development context rather than the tools alone".
- **INTERNAL INCONSISTENCY to flag:** body says 9.1% of all 302,579 commits introduce an issue, yet every tool is 17.4% or higher; a pooled rate cannot be below every component. The two figures use different denominators (probably the per-tool figure is over commits that touch analysable files, or over commits with at least one analysed issue, but the paper does not say). The abstract headline ("more than 15%") and the 9.1% cannot both describe the same population. Treat both as unreconciled; I could not resolve this from text. (The search-snippet abstract excerpt that said "9.1%" suggests the authors know the lower figure.)
- **Net impact (Fig. 8, RQ3):** smells fixed 439,817 vs introduced 432,748, net reduction 7,069 (AI commits fix slightly *more* smells than they introduce). Correctness and security: introduced exceed fixed; security introduced about 1.5x fixed (exact fixed counts not in text).
- **Persistence 22.7%:** 105,364 of 464,900 *tracked* issues present at HEAD (464,900 is 19,466 fewer than the 484,366 introduced; reason for the gap not stated). Horizon = time from introducing commit to HEAD (about Feb-Mar 2026), so exposure varies by cohort:

| Cohort | Commits | Issues | Surviving | Survival |
|---|---|---|---|---|
| more than 9 months | 17,612 | 21,421 | 4,893 | 22.8% |
| 6-9 months | 56,955 | 89,135 | 17,307 | 19.4% |
| 3-6 months | 79,986 | 111,551 | 31,492 | 28.2% |
| less than 3 months | 147,979 | 242,793 | 51,672 | 21.3% |

  Not monotonic; the authors note this. Cohorts sum to 302,532 commits, 464,900 issues.
- **"Who fixes the rest, how fast":** no time-to-fix distribution, no hazard curve, no fixer identity (human vs AI) analysis. Only anecdotes: one smell fixed within hours; Stirling-PDF lint issue fixed next day; firecrawl undefined variable (Devin) fixed after 42 days; Devin `requests.get` without timeout (Dec 2024) still present. Cumulative surviving issues: "a few hundred" early 2025 to over 100k by Feb 2026 (Fig. 9), which mostly tracks the growth in AI commit volume, not a rate. Survival by issue type (smell vs correctness vs security) is not reported, so "22.7%" is dominated by smells (89% of the pool) and says nothing specific about security or correctness persistence.
- **Splits not reported:** no repo-maturity, star-count, review-intensity, team-size or task-type splits (listed as future work); no survival or introduction by tool. The statement that issues "persist regardless of repository size or popularity" in the Discussion has no supporting table in the body.

### 4. Nulls, limitations (authors' and mine)
- Authors: public 100+-star Py/JS/TS only; explicit-trace commits only; mixed human/AI commits; issue matching across revisions imperfect; survival underestimated when files are deleted or rewritten; static-analysis false positives; security count mixes real vulnerabilities and latent patterns; architectural, documentation and test debt out of scope; no human baseline.
- Net-reduction result for smells (more fixed than introduced) is a mild null/positive for the "AI only adds debt" narrative and is easy to miss in the abstract.
- Mine: no control for task type or commit size (larger commits mechanically introduce more issues; Claude's 56.8 commits/repo and bulk-generated repos such as claudes-c-compiler with 3,957 commits could dominate counts); counts are of issues not defects; no weighting by repo, so a few prolific repos may drive totals (concentration not reported); Copilot's 4,487 repos vs Devin's 298 means the per-tool contexts differ sharply.

### 5. Outcome type
Purely static-analysis findings (lint, Pylint, Semgrep rule hits) plus their persistence at HEAD. No defect reports, bug-fix linkage, incidents, runtime failures, or review data. Anecdotal NameError/SQL-injection examples are illustrations, not measured outcomes.

## Tier & era grading
- **Tier: B (structured observational, large-N, no randomisation, no counterfactual), low end.** Large and carefully validated on attribution, but it lacks a comparison group, so it cannot carry any "AI vs human" claim, and its outcome is a proxy. Single institution, preprint, peer-review not confirmed. Recommend citing as B for *descriptive prevalence and persistence of static-analysis findings in AI-attributed commits* only.
- **Era: E3 predominantly, but not cleanly separable.** Attribution signals (bot actor logins such as `copilot-swe-agent[bot]`, "Cursor Agent", Devin, Claude Code, `noreply@anthropic.com` co-author trailers) are overwhelmingly agent-mode artefacts, and volume rises sharply from mid-2025. Copilot (39% of commits) may include Co-authored-by trailers from non-agent modes, and Claude is "all variants"; the paper does not split modality per commit. Tag E3 with a caveat that an unquantified minority may be chat/inline-assisted commits. Not usable as E1 autocomplete evidence. By tool: Claude Code, Cursor Agent, Devin, Copilot coding-agent, Gemini CLI/agents are E3; per-commit mode unverified.
- **Independence:** independent of vendors (no stated funding). Dataset provenance: self-built from GH Archive and GitHub API; not derived from AIDev or the other corpora in this programme as far as the text states, but both rely on public star-filtered GitHub repos, so population overlap is likely and unquantified. Same group (Liu/Lo) previously published ChatGPT code-quality work they cite (self-citation, E2). Provenance-cluster tag suggestion: "GitHub public-repo trace mining" (shared with AIDev-style corpora).

## Measured vs self-reported
All findings are **measured** (tool output on commits). No self-reported data. The only human judgement is the authors' validation samples (n=100 commits, n=99 issues). No perceived-vs-measured delta available.

## Can / cannot support — verdicts
- **Can support:** (a) a prevalence floor: in public star-filtered repos, a substantial minority of explicitly AI-attributed commits (9.1% pooled, 17.4-29.1% per tool on the stated per-tool basis) add at least one linter/Semgrep finding; (b) smells dominate (89.3%) with correctness 6.0% and security 4.7%; (c) at least 22.7% of tracked AI-introduced findings remain at HEAD, including 4,893 older than nine months; (d) methodology: explicit-trace attribution can be validated at about 99% precision. Supports RQ3 (failure map, quality side) and RQ4 (quality-debt cost signal) as directional, Tier B, E3-with-caveat.
- **Cannot support:** any claim that AI code is *worse than* human code (no baseline; human code also carries lint issues and smell persistence); any defect, incident, stability or velocity claim (RQ5); any claim about severity or exploitability; cost in effort or money; tool ranking (usage and context confounded, authors say so); seniority or maturity effects; generalisation to private, small, or non-Py/JS/TS code; the "debt persists" framing as causal harm (22.7% survival of lint findings might equal or beat the human rate).
- **Do not quote** "more than 15% of commits introduce an issue" without the caveats above: no baseline and unreconciled with the 9.1% pooled figure.

## Red flags / things the orchestrator should know
1. **No human baseline** (stated explicitly by the authors). Headline rates are uninterpretable as an AI penalty. A tension-4 cross-check against GitClear/Uplevel is therefore only qualitative.
2. **Static-analysis-as-quality proxy:** lint rules (unused variable, broad except, shadowing) are style-level; about 14% of reported issues were false positives in the authors' own validation; no severity grading; security count includes latent patterns. This is a long way from defects.
3. **Attribution validated for existence, not authorship of the changed lines**; mixed commits acknowledged; selection on commits that self-label as AI (developers who disclose AI use differ from those who do not). Selection direction unknown.
4. **Internal inconsistency 9.1% vs 17.4-29.1%** unreconciled; v1 to v2 shifted survival from 24.2% to 22.7% and other counts, so the numbers are not stable; cite v2 and note v1.
5. **Persistence figure is not a time-to-fix result:** single snapshot at HEAD, overall pooled and dominated by smells, no survival by type, no censoring analysis, no survival comparison with human issues; a recent cohort (less than 3 months) has 21.3% survival, similar to the older ones, which hints that most "survival" may be issues nobody ever looks at (or low-priority lint) rather than ageing debt.
6. Compound volume effects (a few bulk-generated repos) not examined; no per-repo clustering of results.
7. Dataset provenance: possible overlap with AIDev-type corpora and the other trace-mining sources already in the programme; check before treating as independent confirmation. Triangulation value is for "trace-mined public GitHub" cluster only.
8. Peer-review status unknown (arXiv only as of search).
