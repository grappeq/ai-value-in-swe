## What this document is
Observational, within-project longitudinal study of code review across three project-defined eras: pre-LLM (human-centric), LLM-assisted, and agentic. Covers 1.02M reviewed pull requests in 207 GitHub projects, May 2022 to February 2026. Three RQs: (1) adoption practices and their relation to efficiency and review smells; (2) per-PR human/LLM/agent collaboration patterns; (3) explanatory logistic regressions comparing collaboration patterns with traditional factors.

## Full notes

**1. Dataset provenance (unambiguous).** The authors mined the data themselves. They started from 2,490 candidate projects found via GitHub advanced search (>=100 stars, created before May 2022, at least one reviewed PR per month May 2022 to Feb 2026), pulled reviewed PRs and review conversations through the GitHub REST API, and kept 207 projects with more than 400 reviewed PRs in each era. They do NOT reuse the AIDev dataset. They do cite Li, Zhang and Hassan (2025), "The rise of AI teammates in SE 3.0" (arXiv 2507.15003, the AIDev paper; Hassan is at Queen's), but only for the 11-category PR-type taxonomy and the GPT-4.1-mini title/description classification method, which they re-apply to their own PRs (kappa 0.91 against 384 manually labelled PRs). Authors are Queen's, like AIDev's Hassan group, so there is institutional proximity, but no shared corpus. Data selection (continuous review activity, >400 PRs per era) is a different sampling frame from AIDev (which is agent-authored PRs).

**2. Era and practice operationalisation.** Reviewer accounts are labelled human / rule-based bot (GitHub Actions) / traditional ML (Amazon CodeGuru Reviewer) / LLM reviewer (e.g. LlamaPReview) / AI agent reviewer (e.g. Claude Code; the paper also cites the Copilot coding agent in references). Labels come from the GitHub API plus manual reading of each tool's official documentation. Agent labelling was checked on 384 agent-era PRs: 360 showed planning, repository retrieval or commit actions; 24 had comments only and were labelled agent from documentation. The paper does not provide a full tool list in the text; CodeRabbit and Copilot review are not named in the extracted text.
- Eras are per project: pre-LLM = before any generative-AI reviewer participates; LLM era = from first LLM-reviewed PR until first agent-reviewed PR; agent era = from first agent-reviewed PR onward. The agent era is chronological, so LLM reviewers can still appear within it.
- Practices come from soft-DTW clustering (k=3, silhouette 0.40, "fair") of a 30-point series (monthly AI-reviewer rate, resampled to 10 points per era): Gradual AI Adoption 46% of projects (LLM reviewers on 8% of PRs in LLM era; agents on 36% in agent era); Rapid LLM Adoption 22% (n=45; 91% then 93%); Rapid AI Agent Adoption 32% (19% then 76%; includes 12 Microsoft and 3 Google organisation repos).

**3. Measures (the crux).**
- Review efficiency: days from PR creation to final review decision (merged = accepted, closed unmerged = rejected), divided by thousands of lines changed (days/KLOC). A speed measure only.
- Review quality: not measured directly. The paper uses six "review smells" (Doğan and Tüzün) as "indicators of review-process quality risk": Sleeping Review (decision >2 days), Review Buddies (same reviewer, human or AI, reviews >=50% of an author's PRs), Large Changeset (>500 churn lines), Ping-Pong (>3 change-request iterations), Missing Context (empty description or no linked issue), Lack of Review (no reviewer other than the author). Prevalence = share of PRs with at least one smell. Baseline prevalence is 81-84% before AI, so the metric discriminates weakly.
- Not measured: post-merge defects, reverts, follow-up fixes, escaped bugs, comment usefulness or resolution rate, acceptance of AI comments, severity of issues found, reviewer effort or cost.
- Sleeping Review is itself a time measure (>2 days), so it overlaps with the efficiency metric.

**4. Effects.**
- Table IV (efficiency in days/KLOC, change vs pre-LLM baseline; significance marked * in the table, significance stated in text): Gradual: baseline 8.5, LLM -1.6, agent -2.5 (significant). Rapid LLM: baseline 5.4, LLM +0.6, agent -0.1 (not significant). Rapid Agent: baseline 10.4, LLM -3.4, agent -4.5 (significant). Text: significant gains only in agent era for Gradual and Rapid Agent.
- Smell prevalence (baseline 83.8 / 83.6 / 81.0%): Gradual +3.8 (LLM), +2.0 (agent), authors report no improvement and no significant increase; Rapid LLM +8.0 and +4.4 points, both significant; Rapid Agent +4.4, +2.5. Review Buddies baseline 47.8 / 45.9 / 36.4%; increases of +15.1/+15.6 (Gradual), +26.0/+23.2 (Rapid LLM, significant), +16.6/+12.4 (Rapid Agent). Units (points vs percent) are not clear in the table caption.
- Interpretation of the quality result: the abstract says efficiency gains "do not translate into better review quality". In the data this is a smell-prevalence non-improvement (small, mostly non-significant rises under Gradual and Rapid Agent; significant rises under Rapid LLM). It is a process-proxy result, not evidence about defects.
- Collaboration patterns (10 found via Markov-chain EM, lowest BIC; Table V): in the agent era Agent-Init and Multi-Agent rank R1-R2 versus Human-Only R2-R3 under Gradual and Rapid Agent; no difference under Rapid LLM (Human-Only ranks first, 61% resolved in two turns). In LLM era LLM-Assist is slower than Human-Only in all three practices. Smell prevalence 69-76% Human-Only vs 78-94% AI-involved; driven by Review Buddies (16% human-only vs 60% LLM-involved and 53% agent-involved on average). Mechanism noted by authors: in 75-95% of Agent-Init/Multi-Agent PRs the agent posts a summary and the human replies once.
- PR types: in Gradual, LLM reviewers over-index on chore (2.0x) and fix (1.2x) in the LLM era; agents on feature (1.4x) and refactor (1.3x) in the agent era (relative participation rate, chi-square).
- Explanatory models (RQ3; 9 efficiency + 27 smell logistic models; outcomes dichotomised at the within-cell median or smell presence; 90/10 split AUC, values not in extracted text; likelihood-ratio tests; Imp% = relative change in predicted probability): pre-LLM, author experience (Imp -17 to -22% on delay) and PR type dominate; LLM era, LLM/bot patterns raise delay; agent era, collaboration pattern is dominant for efficiency under Gradual and Rapid Agent; under Rapid LLM traditional factors are non-significant and AI patterns are associated with higher delay. Commits (+27 to +70) and inline threads (+26 to +51) raise Sleeping Review in every era. Agent-involved patterns associated with Large Changeset (+25 to +48 Gradual; +20 to +54 Rapid Agent) and with Review Buddies. The abstract's ranking (collaboration patterns strongest for efficiency once LLM/agent reviewers participate; review activity and PR type remain important across eras) is supported by the text; it is a ranking of factor impact on a dichotomised speed outcome and applies to efficiency, not quality.
- Heterogeneity: the three practices diverge sharply (Rapid LLM shows no speed gain and more smells). No seniority or codebase-maturity heterogeneity is analysed.

**5. Design.** Within-project era comparison (project is its own baseline), Wilcoxon signed-rank with Bonferroni, Scott-Knott ESD, chi-square. No control group of non-adopting projects, no adjustment for calendar trends, PR mix, team change or the pre-existing trend; adoption timing is self-selected by projects. RQ3 is explicitly explanatory, not causal. Exact p-values, effect sizes beyond the deltas, per-group Ns and CIs are not given in the text.

**6. Limitations stated by authors.** Agent era is chronological, not per-PR (LLM reviewers persist); minor LLM patterns (<5%) dropped from Table V; RQ3 models explanatory not causal; tools evolve quickly so patterns may shift; motives for human-AI choices unexplained (future interviews/surveys).

**7. Authored vs reviewed.** The study is about who reviews. Whether the PR author is an agent is not distinguished: PRs are typed by purpose, and author experience is measured as prior commits. Agent-authored PRs are not separated from human-authored ones, so review-of-agent-code effects are not isolated. Agent comments are identified from reviewer account labels only.

## Tier & era grading
- Tier: B (large-scale structured observational telemetry on public GitHub data, within-project baseline, no randomisation and no external counterfactual). Not A: no control group, no causal design. Not C/D: academic, large N.
- Era: split by period studied. Pre-LLM period is a pre-AI baseline. LLM-assisted period is E2 (LLM review bots/apps). Agent-era findings are E3, with the caveat that the agent era is project-level chronological and mixes residual LLM reviewers; AI-agent reviewers are labelled from tool documentation and 94% (360/384) of sampled PRs showed agentic behaviour. Findings that mix the periods (practice-level comparisons) should be quoted with both era labels.
- Independence/COI: independent academic authors; no funding or vendor stated. Dataset provenance: own mining (not AIDev); only PR-type taxonomy method is borrowed from Li et al. (2025). Projects include Microsoft and Google organisation repos, but no vendor authorship. Population is open-source GitHub projects with >=100 stars (selection toward active, survivorship-biased projects; projects needed continuous review for ~4 years).
- Version: v1 only; no preprint substitution needed (arXiv is the only version).

## Measured vs self-reported
All findings are measured from public GitHub review metadata. No self-reported data, no perception-reality delta. Reviewer-type labels are researcher-assigned (documentation-based), and PR types are LLM-classified (kappa 0.91), so some construct measurement is inferential even though outcomes are mechanically computed.

## Can / cannot support — verdicts
- CAN support: directional evidence that AI-reviewer participation in the agent era is associated with faster time-to-decision per KLOC in two of three adoption groups (T7); that adoption path matters (heavy early LLM adoption showed no speed gain); that agent-initiated and multi-agent review can shorten human back-and-forth by providing a summary first; descriptive evidence on how AI reviewers are used by PR type; bottleneck-relevant observation that agent-involved review concentrates on larger changesets.
- CANNOT support: any claim that AI review improves or harms defect rates, escaped bugs or code quality; any claim about review effectiveness (issues found, comment value); causal claims; effect sizes for exec-brief use without an E3 label and the proxy caveat; claims about agent-authored code; seniority or mature-codebase claims.
- Confidence: medium for the speed associations (large N, within-project baseline, but no counterfactual); low for the "quality" reading (process proxy with 80%+ baseline prevalence and a definitional artefact in Review Buddies).

## Red flags / things the orchestrator should know
1. "Review quality" is NOT a defect outcome. It is smell prevalence, a process proxy, and one of the three headline smells (Sleeping Review) is a time measure. The abstract's "efficiency gains do not translate into better review quality" is a non-improvement in proxy smells, not evidence of unchanged or worse defect rates. In the data the quality result is a mix of small non-significant changes (Gradual, Rapid Agent) and a significant rise in smells (Rapid LLM), not a measured null on defects. Do not quote it as "AI review does not improve quality" without the proxy caveat; do not use it for RQ5 stability claims.
2. Review Buddies is largely mechanical: a single AI account that reviews most of a project's PRs necessarily reviews >=50% of each author's PRs. The headline smell increase (16% to 53-60%) is therefore close to a definitional consequence of bot adoption.
3. Dataset overlap with AIDev: none by construction (own mining via GitHub API; AIDev not used), but it borrows the AIDev PR-type taxonomy/classifier. Same institutional group family (Queen's), so provenance-cluster tag at most "adjacent institution", not shared data. Treat as independent of AIDev-based sources for data, not for taxonomy.
4. Speed gains are per-KLOC time to decision, with no counterfactual; gains are largest where baseline latency was highest (Rapid Agent 10.4 days/KLOC), so regression to the mean and concurrent trends are not excluded. Agent-Init PRs skew to chore and larger changesets.
5. Review of PR authored by agents vs humans is not separated. Bottleneck displacement (tension 6): not tested directly (no queue-length metric), though Large Changeset association hints at larger loads.
6. Table V/VI and some Table IV significance markers were partly garbled in HTML; check the PDF before quoting any single Imp% or asterisk. Exact p-values and CIs are absent from the text.
7. Specific tools: only Claude Code and LlamaPReview appear as examples in the text; do not claim CodeRabbit or Copilot review findings.
8. Recency check: published July 2026, under 12 months old; no later version or retraction found.
