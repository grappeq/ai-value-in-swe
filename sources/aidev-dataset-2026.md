## What AIDev is

**Two-vintage structure — this matters for anyone treating "the AIDev dataset" as one fixed population:**

| | 2507.15003 (Jul 2025 vintage) | 2602.09185 (Feb 2026 vintage) |
|---|---|---|
| Data cutoff | 22 Jun 2025 | 1 Aug 2025 |
| Full dataset | 456,535 PRs / 61,453 repos / 47,303 developers | 932,791 PRs / 116,211 repos / 72,189 developers |
| Curated/"popular" subset threshold | **>500 GitHub stars** | **>100 GitHub stars** |
| Curated subset size | 7,122 PRs / 856 repos / 1,240 developers | 33,596 PRs / 2,807 repos / 1,796 users |

The full dataset roughly **doubled** in six weeks between vintages (driven overwhelmingly by OpenAI Codex, which alone accounted for 411,621 of the 456,535 PRs in the earlier snapshot — **~90% of the total from one agent**). The curated subset grew **4.7×** (7,122 → 33,596) over the same window — disproportionate to the ~2× growth of the full corpus, and explained mainly by the star threshold dropping 500→100 (repo count in the curated slice grew ~3.3×, from 856 to 2,807), not by time passing. **Consequence: "AIDev-POP" or "the curated subset" means two different populations depending on which paper's vintage a downstream source used**, and this is not always stated explicitly by downstream papers. `task-stratified-agents-2026` and `unreviewed-ai-prs-2026` both use the >100-star, 33,596-PR (2602.09185) vintage; `agents-vs-ides-2026` uses the full 932,791-PR corpus, unfiltered by stars, for its own >10-star/≥10-agentic-PR treated-repo criterion.

**A live illustration of this instability:** the predecessor paper's own headline case-study acceptance rates on the >500-star, 7,122-PR vintage (Finding #2) were Codex 64%, Devin 49%, Copilot 35%. `task-stratified-agents-2026`, working from the >100-star, 33,596-PR-derived, further-filtered 7,156-PR sample, reports Codex 77.9%, Devin 61.6%, Copilot 68.0% — **Copilot's acceptance rate very nearly doubled (35%→68%) between vintages.** This is not necessarily an error in either paper (different filtering, different time windows, different repo sets) but it is a concrete demonstration that "the AIDev acceptance rate for Copilot" is not a stable fact — it depends on which dataset snapshot and filter chain produced it.

**Construction / agent-attribution method (documented in full only in 2507.15003 §3.1; the 2602.09185 dataset paper does not repeat it):**

PRs are identified via targeted **GitHub REST API search queries**, one per agent, each keyed to a distinct behavioural/metadata signal. The queries themselves are stated as **"adapted from PRarena"** (`github.com/aavetis/PRarena`), a third-party open community list — i.e. the attribution scheme is not independently derived from first principles by the authors, but inherited and lightly adapted from an external source.

| Agent | Detection signal | GitHub search query | Start date used | Basis for start date |
|---|---|---|---|---|
| OpenAI Codex | Branch-name prefix | `is:pr head:codex/` | 2025-05-16 | Official release announcement |
| Devin | Bot account login | `is:pr author:devin-ai-integration[bot]` | 2024-12-24 | Official release notes |
| GitHub Copilot | Branch-name prefix + manual login check (`user.login == "copilot"`) | `is:pr head:copilot/` | 2025-01-01 | **Conservative default** — "no official release date found" |
| Cursor | Branch-name prefix | `is:pr head:cursor/` | 2025-01-01 | **Conservative default** — "no official release date found" |
| Claude Code | Commit/PR-body co-author trailer | `is:pr "Co-Authored-By: Claude"` | 2025-02-24 | Official release notes |

This is a **pure metadata/behavioural heuristic** — string-matching on branch prefixes, bot account names, or a commit trailer — not a machine-learning classifier, and not a manually-reviewed sample of individual PRs at any scale.

**Validation of the attribution method: none reported, in either paper.** No precision, no recall, no false-positive-rate estimate, no manually-labelled ground-truth sample, no confusion matrix, appears anywhere in the ~1,500 combined lines of both papers' primary text. The only "quality" step mentioned is the start-date filter (to exclude pre-release noise) and the Copilot login re-check — neither is a validation of whether the heuristic correctly separates agent-authored from human-authored PRs at any measured rate.

**Curated-subset enrichment (2602.09185, Table 1):** beyond the core PR/repo/user metadata, the curated (>100-star) subset adds `pr_comments` (39,122), `pr_reviews` (28,875), `pr_review_comments` (19,450, inline/file-level), `pr_commits` (88,576), `pr_commit_details` (711,923, file-level diffs/patches), `related_issue`/`issue` (4,923/4,614), `pr_timeline` (325,500 events), and an **automated `pr_task_type` annotation (33,596 records) — a GPT-based classifier assigning each PR to a Conventional-Commits category** (feat/fix/docs/chore/style/ci/build/refactor/test/perf/revert/other). This task-type layer is itself an unvalidated LLM annotation (no inter-rater check, no accuracy figure reported) and is the exact layer `task-stratified-agents-2026` builds its entire T1–T11 mapping exercise on top of — one unvalidated automated layer (agent attribution) feeding a second unvalidated automated layer (task labelling).

## Known biases and limitations

**Neither paper contains a dedicated "Limitations" or "Threats to Validity" section.** The caveats below are either the authors' own words scattered through the findings/discussion, or reasonably inferred from the construction method above.

**Authors' own stated caveats:**

1. **Self-disclosure selection bias (the single most important caveat; Finding #9, 2507.15003, verbatim):** *"Among the Agentic-PRs, we found that Devin, GitHub Copilot, and Cursor explicitly indicate their authorship in commit metadata. In contrast, OpenAI Codex and Claude Code attribute their contributions to human developers... OpenAI Codex provides no attribution at all"* in commit metadata (detected only via the branch-prefix query proxy), and Claude Code's co-author trailer *"can be disabled"* by the user. **Consequence: AIDev structurally captures only agent usage that leaves a discoverable, undisabled signature.** Any Claude Code user who turns off the co-author trailer, or any Codex/Copilot/Cursor user whose workflow doesn't produce the default branch-naming convention (renamed branch, squash-merge that drops the trailer, a wrapper tool, a rebase), is invisible to this dataset by construction. This propagates to every downstream percentage as an unknown, unquantifiable undercount — and the undercount rate is very unlikely to be uniform across agents, since the ease of "hiding" from the heuristic differs by detection mechanism (a bot-account login is harder to accidentally lose than a co-author trailer).
2. **Local-usage underrepresentation (Finding #1, 2507.15003, verbatim):** *"since these two tools [Cursor and Claude Code] are mainly used locally, their relatively low [GitHub PR] usage... suggests that their characteristics would be better understood through analysis within local environments rather than relying solely on GitHub data."* The dataset only sees GitHub-PR-visible activity; agents used in local/CLI/IDE-integrated workflows that don't culminate in a tracked PR (or are used for exploration, review, or non-PR tasks) are structurally absent — and this affects precisely the two tools most associated with local-first usage.
3. **OSS-only, GitHub-only, popular-repo-skewed:** the full dataset is GitHub-hosted OSS only (no enterprise/private repos, ever); the enriched curated subset that most quantitative downstream analysis actually uses additionally requires a star-count floor (500 in the first vintage, 100 in the second) — this excludes the long tail of small/obscure OSS entirely from the artefact-rich data (comments, reviews, diffs) that carries almost all of the interesting downstream analysis.
4. **Single-agent volume dominance:** OpenAI Codex alone was ~90% of the predecessor-vintage full dataset (411,621 / 456,535 PRs). Any unstratified aggregate statistic drawn from "AIDev" is effectively a Codex statistic with the other four agents as a thin garnish; all three of our dependent sources do stratify by agent, but this is a trap for any future unstratified citation.
5. **Conservative, evidence-free start dates for two of five agents** (Cursor and Copilot both set to 2025-01-01 "no official release date found") — could understate true early-period activity, though the authors note the cumulative-PR curves show negligible pre-March-2025 volume for either tool regardless.
6. **Reviewer-bot provider lock-in (Finding #7, 2507.15003):** review bots are frequently from the *same vendor* as the coding agent they review (e.g. `copilot-pull-request-reviewer[bot]` performs 91.0% of bot reviews on Copilot PRs) — meaning "reviewed" in this dataset often means "reviewed by the same vendor's own bot," a construct-validity wrinkle `unreviewed-ai-prs-2026` has had to explicitly work around.

**Inferable biases, not stated by the authors:**

7. **No attribution-heuristic validation anywhere** means every downstream percentage (acceptance rates, review coverage, complexity deltas) inherits an unknown, unquantified rate of both false positives (e.g. a human developer who happens to name a branch `codex/refactor` for unrelated reasons) and false negatives (real agent PRs the heuristic misses) from an unaudited base layer. This is the single largest hidden-uncertainty source underneath every AIDev-derived claim in this evidence base.
8. **No developer-seniority or professional/hobbyist characterisation anywhere** in either paper — inherited by every downstream source (already flagged independently in `agents-vs-ides-2026`'s own record).
9. **Structural time-confounding across agents:** because each agent has its own uncontrollable public-release date, any cross-agent comparison at a fixed calendar date is inescapably comparing agents at different points in their own deployment maturity — `task-stratified-agents-2026` names this explicitly as an inherited limitation.
10. **Snapshot/versioning instability, no fixed release policy stated:** the dataset has already been re-published once at roughly double the size and a different star threshold (Jul 2025 → Feb 2026); nothing in either paper commits to a versioned, immutable release schedule, so any future citation of "the AIDev dataset" needs the specific HuggingFace/Zenodo pull date, not just the paper citation, to be reproducible.
11. **Survivorship not tracked:** no stated mechanism for handling PRs/repos that were later deleted, made private, or had their GitHub history rewritten between the original scrape and any re-scrape.

## Grading — as an instrument, not a findings source

PROTOCOL §3's Tier A–D scale grades *evidentiary claims*; AIDev itself is a **data instrument that other papers build claims on top of**, not a claim-bearing source in its own right. Its own predecessor paper's "findings" (case studies 1–3 in 2507.15003) are thin, mostly single-example demonstrations (e.g. one repository, one developer, three days, for the headline throughput comparison) with no statistical testing, no confidence intervals, and no control group — **these should never be cited in our evidence table as effect sizes**; if ever referenced, they carry anecdotal/illustrative weight only, well below even Tier C.

- **As an instrument: "usable but unaudited."** The attribution method is a coherent, documented, metadata/behavioural heuristic (not ad hoc), but it is **unvalidated** (no precision/recall reported by its creators, no independent audit located as of this check — see Follow-up leads for the closest thing found), with an **acknowledged, agent-specific asymmetry in detectability** (self-disclosure bias, point 1 above) and an **acknowledged GitHub/OSS/local-usage blind spot** (points 2–3 above). It is adequate for large-N descriptive and directional work — which is exactly how our three dependent sources use it — but not rigorous enough to support precise point-estimate claims without independent corroboration of the attribution step itself, and every dependent source should carry this caveat forward rather than treating "AIDev-derived" as equivalent to "validated instrument."
- **Independence:** Academic, Queen's University (Hassan's lab). **No funding, grant, or acknowledgments statement found in either paper's text** (checked directly against the primary PDF text, not just the abstract) — this is an absence of disclosure, not a confirmed "no vendor funding"; it should be recorded as *undisclosed*, not as a clean bill of independence. No vendor affiliation identified for any of the three authors. No Tier-D flag is warranted on current evidence, but the absence of any COI statement (common in this specific sub-literature, per patterns already noted in several dependent-source records) means this should not be over-stated as "verified independent" either.

## Triangulation implications for §3

**Independent authorship does not make findings independent when the population is shared, and this evidence base now has a confirmed, non-speculative instance of exactly that problem.** `agents-vs-ides-2026`, `task-stratified-agents-2026`, and `unreviewed-ai-prs-2026` are written by three genuinely distinct, non-overlapping academic teams (CMU; Trieste/KCL/UCL; Nicolaus Copernicus University respectively) with no shared authors — by PROTOCOL §3's independence test ("different organisations, not retellings of the same rollout, no shared vendor sponsorship") they would, on authorship grounds alone, look like three independent Tier A/B legs. But all three ultimately draw their population of agent-authored PRs from the same unvalidated attribution heuristic constructed by one three-person Queen's University lab, applied to overlapping (and in `unreviewed-ai-prs-2026`'s case, *identical*) slices of the same underlying GitHub scrape. Any claim that rests on the *existence, count, or rate* of agent-authored PRs, agent identity, or the boundary between "agent-authored" and "human-authored" — which is most of what these three papers measure — is a claim about **one shared, unaudited measurement instrument**, not three independent measurements of the same phenomenon. Concretely: the ~18–39% quality-debt figures in `agents-vs-ides-2026`, the task-type acceptance gradient in `task-stratified-agents-2026`, and the 84%/61.38%/30.1% review-coverage figures in `unreviewed-ai-prs-2026` should be counted as **one voice, not three**, for any PROTOCOL §3 triangulation tally (the ≥3-independent-Tier-C-sources rule, and the general "how many legs does this claim stand on" question for Tier A/B sources) — exactly the same demotion already applied to the CMU lab's three papers (`he-2026-2x-mandate`, `agents-vs-ides-2026`, `cursor-velocity-quality-2025`) for authorship-overlap reasons, but here the mechanism is dataset-overlap rather than authorship-overlap, and it is if anything a *harder* dependency to see, because the papers' authors genuinely are different people who did genuinely different analytic work — the shared risk sits one layer down, in the attribution heuristic none of them re-validates. Recommend the orchestrator treat any future AIDev-rooted paper (the "likely dependent" list above, plus Rahman et al. once extracted) as joining this same single provenance cluster by default, and require a positive statement of *independent data collection* (as `cursor-velocity-quality-2025` and `agent-maintainability-2026` both have) before crediting a new source as a genuinely separate triangulating leg for any claim about agent-PR rates, acceptance, or attribution-dependent quality metrics.
