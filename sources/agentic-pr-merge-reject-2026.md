## Grading (PROTOCOL §2–§3)

- **Tier: B** — "Large-scale telemetry without randomisation, ... multi-company code-quality analyses. Carries claims with caveats." This is exactly that shape: 9,799 human-reviewed PRs at the quantitative layer, 717 manually double-coded PRs (κ ≈ 0.90–1.0) at the qualitative layer, drawn from real GitHub activity, no randomisation or counterfactual. Not Tier A (no experimental/counterfactual design — it is observational classification of what already happened). Peer-reviewed acceptance at MSR 2026 supports Tier B rather than Tier C; it is not a practitioner blog.
- **Era: E3 (agentic)**, unambiguously. All five studied agents — OpenAI Codex, Devin, GitHub Copilot (agent mode), Cursor, Claude Code — are autonomous/semi-autonomous PR-generating agents, not autocomplete or chat-assist tools. Every finding in this source is E3.
- **Independence:** Academic, no vendor funding statement found in the fetched content (no acknowledgements/funding section was present in what was extracted — flagged as unverified rather than assumed clean). **Key independence caveat: the dataset is not the authors' own collection** — see Dataset Provenance below. This caps how much triangulation weight this source can add alongside any other paper drawn from the same underlying dataset.
- **Task type:** T7 (Code review / PR merge-decision-making) is the primary tag — the paper's unit of analysis is the review/merge decision itself, not a specific SDLC task category. The underlying PR content spans unknown/unspecified task types (bug fixes, features, etc.); the paper does not break rejection/merge reasons out by underlying task type, which is itself a gap relevant to RQ3's task-characteristic question.
- **Relevance to us:** High. This is one of the only close-to-rigorous, large-N, peer-reviewed, agentic-era studies of *why* agent PRs fail or succeed, directly targeting RQ3 (failure map) and materially correcting a naive "rejected PR = agent failure" reading that a less careful reader (or an exec narrative) might otherwise adopt.

## Dataset Provenance (explicit, per task instructions)

**Not the authors' own collection.** The paper is built entirely on the **AIDev dataset (Li et al., 2025)**, a large public dataset of agent-authored GitHub PRs. Per independent web verification (not from this paper itself): AIDev comprises ~932,791 Agentic-PRs from five agents (Codex, Devin, Copilot, Cursor, Claude Code) across ~116,211 repositories, with curated high-quality subsets restricted to higher-star repos. This paper's working population is a further restriction: **closed Agentic-PRs from repositories with ≥500 GitHub stars**, filtered down as follows:

1. 11,048 closed Agentic-PRs (6,774 merged; 4,274 rejected) — the ≥500-star AIDev subset
2. → 9,799 after excluding bot-only-reviewed PRs (no human review comments at all)
3. → 717 stratified-sampled for manual dual-coding (353 rejected, 364 merged)

**Independence/triangulation flag:** during verification I found at least one other MSR 2026 paper on the *same narrow topic* — "Understanding the Rejection of Fixes Generated by Agentic Pull Requests – Insights from the AIDev Dataset" (arXiv 2606.13468; authors Abujadallah, Arabat, Sayagh — a different institution/team) — which independently analyses rejection reasons for agent-authored fixes, also from AIDev (306 non-merged PRs, 14 reasons in 4 high-level categories, reporting a 46.41% rejection rate for fixes specifically). This is a *different research group* with a *different coding scheme and different sub-population* (fix-PRs only vs. all closed PRs; 4 categories/14 reasons vs. this paper's 3 categories), so it is genuinely independent analysis — but **both studies share the same underlying AIDev data collection**, meaning any systematic bias, mislabeling, or coverage gap in how AIDev itself identifies/classifies "agentic PRs" would propagate into both. Treat convergent findings across these two papers as corroboration at the *interpretation* layer, not as fully independent data-layer triangulation. I did not extract 2606.13468 in full (out of scope for this task) — flagging its existence and abstract-level shape only.

## Methodology notes

- Four annotators, dual independent coding per PR, coding scheme developed iteratively via pilot inspection, disagreements resolved by discussion, ambiguous cases conservatively defaulted to "Unknown" rather than forced into a substantive category (a methodologically conservative choice that likely *understates* clear findings in both directions).
- Inter-rater reliability: Cohen's κ ≈ 0.90 for the rejection-reason taxonomy; κ = 1.0 for the merged-PR interaction-pattern taxonomy. High agreement — a genuine strength.
- Stratified sampling for the 717-PR manual layer, aimed at coverage across agents and repositories (not simple random sampling), which is appropriate for ensuring low-volume agents like Claude Code (n=213 in the full 9,799) aren't invisible, but means per-agent percentages below rest on small manual-coding sub-samples for the smaller agents (see caveats per finding).
- **Explicitly not measured / stated limitation:** no effort/cost metrics — no review duration, no comment-volume counts, no quantification of human-intervention cost. No time-to-merge or PR-size (LOC) variables reported. This is a direct null relevant to RQ4 (thin cost data is itself expected per protocol's pre-registered RQ4 expectation).
- **Related-work positioning:** the paper does not have a separate "Related Work" section; prior work is folded into a short Motivation section citing PR-decision literature (Golzadeh et al. 2019; Wang et al. 2021), AI-assisted code review (Cihan et al. 2024; Palvannan & Brown 2023), productivity studies (Peng et al. 2023; Cui et al. 2025), and Copilot security (Pearce et al. 2021). **No prior taxonomy of agentic-PR failure/rejection reasons is cited as related work** — the paper frames itself as filling a gap left by outcome-only metrics ("merge rates or approval frequencies... provide limited insight into how review decisions are formed"), not as extending or contesting a prior taxonomy. Given the near-simultaneous, independently-arrived-at 2606.13468 (above), this looks like a genuinely nascent sub-literature (multiple groups converging on the same gap at once in 2026) rather than one paper building on established priors — consistent with the protocol's expectation that formal agentic-era papers are scarce and freshly emerging.
- **External validity limits stated by the authors:** restricted to high-star (≥500) open-source repositories, five agents only, may not generalise to smaller projects, proprietary/enterprise settings (which is our actual population of interest), or future agent systems.

## Findings

**F1 — Rejection is not mostly "the agent was wrong."** Of 353 manually-coded rejected PRs, only 126 (35.7%) reflected a clear, observable agentic failure (failing checks/tests, broken changes). 110 (31.2%) were rejected for non-agentic/workflow reasons (duplicates, superseded work, inactivity, test PRs). 117 (33.1%) had no observable decision rationale at all ("Unknown" — silent closures, insufficient evidence). Measurement basis: measured (manual content analysis of PR/review artifacts with dual coding, κ≈0.90), not self-report. **Can support:** a caution against treating rejection *rate* as a direct agent-quality/failure-rate signal — roughly two-thirds of rejections in this sample are not attributable to demonstrated agent error. **Cannot support:** a claim about the *true* underlying agentic failure rate, since the 33.1% "Unknown" bucket is large and conservatively assigned — the true AF share could be anywhere between 35.7% and ~69% depending on how Unknowns resolve.

**F2 — Most successful (merged) agentic PRs show no visible human steering, but a meaningful minority require it.** Of 364 manually-coded merged PRs: 288 (79.1%) merged with no observable feedback loop or reviewer commit; 28 (7.7%) went through a feedback loop (reviewer comment → agent-only revision); 28 (7.7%) required human intervention (reviewer made direct commits before merge); 20 (5.5%) were ambiguous/unknown. Combined, 56/364 (15.4%) of merges required explicit human involvement (feedback or direct commits) to succeed. Measurement basis: measured (interaction-trace coding, κ=1.0). **Can support:** "most agentic PRs that get merged, merge without visible human correction" as a directional claim for this OSS, high-star population. **Cannot support:** a claim that 79.1% of agent contributions are "fully autonomous quality work" — the paper does not verify post-merge correctness/quality, only absence of an observable feedback/intervention trace before merge.

**F3 — Large, systematic heterogeneity across agents in *why* PRs are rejected.** Within the rejected-PR manual sample: Devin (n=153 rejected in sample) showed 24.2% Agentic Failure / 45.1% Non-Agentic Failure / 30.7% Unknown, versus Codex (n=113 rejected in sample) at 47.8% AF / 16.8% Non-AF / 35.4% Unknown. Copilot (n=57) and Cursor (n=22) showed "mixed" distributions (exact percentages not extracted in full detail from the fetched summary — flagged as a gap; the underlying table would need direct verification against the PDF/HTML tables for exact Copilot/Cursor cell values). Measurement basis: measured. **Can support:** agent choice materially changes both the volume and the *character* of PR rejection — not a uniform "agentic failure rate" across tools. **Cannot support:** a ranking of "best" agent, since population/task assignment across agents is not controlled (different agents may be used on systematically different repos/tasks/organisations within the AIDev sample).

**F4 — Large, systematic heterogeneity across agents in how much human correction merged PRs need.** Copilot: 59.2% of its manually-coded merged sample (n=49) involved a feedback loop or human intervention (13 FL + 16 HI = 29/49). Devin: 23.4% of its merged sample (n=107) needed FL/HI (14 FL + 11 HI = 25/107). Codex: only 0.6% needed HI and 0% FL (n=167 merged). Cursor: 3.0% FL, 0% HI (n=33 merged). Claude Code: 0% FL or HI, but on a very small manual sample (n=8 merged) — **explicit small-n caveat, not statistically meaningful on its own.** The paper states human involvement in merges "was concentrated in Copilot and Devin PRs, which accounted for 54 of the 56 cases labeled as feedback loop or human intervention" — i.e. Codex+Cursor+Claude Code merges are overwhelmingly autonomous-appearing, Copilot+Devin merges much less so. Measurement basis: measured. **Can support:** a strong within-dataset signal that different agentic tools produce PRs needing very different amounts of reviewer effort to land — directly relevant to RQ4's review-overhead question even though no time/cost units are attached. **Cannot support:** causal attribution to agent capability per se, since repo/task/reviewer-population confounds are not controlled for.

**F5 — Dataset-level (9,799 PR) merge rates by agent, not manually verified but from the full quantitative layer.** Codex: 2,834/3,989 merged = 71.0%. Devin: 1,813/3,380 = 53.6%. Copilot: 839/1,429 = 58.7%. Cursor: 563/788 = 71.4%. Claude Code: 130/213 = 61.0%. Overall: 6,179/9,799 = 63.1% merged across the full human-reviewed set (vs. an implied 61.3% merge rate — 6,774/11,048 — in the pre-bot-filtering full ≥500-star AIDev subset). Measurement basis: measured (raw counts, not manually audited for correctness of the merged/rejected label itself). **Can support:** directional agent-level variation in raw merge rate as background context. **Cannot support:** any causal or quality ranking — no control for task difficulty, repo maturity, or reviewer standards across agents; this is exactly the kind of "PR outcomes alone" metric the paper itself argues is insufficient (see F1/F2).

**F6 — Null: no cost/effort data captured.** The paper explicitly does not measure review duration, comment volume, or the effort cost of human intervention — flagged by the authors themselves as a construct-validity limitation. Relevant directly to RQ4: this is another data point supporting the protocol's pre-registered expectation that agentic-era cost/review-overhead data is thin in the literature. **Can support:** RQ4's "insufficient evidence" pattern. **Cannot support:** any quantitative cost or overhead comparison.

**F7 — Null/scope: no task-type breakdown, narrow population.** The paper does not tag PRs by underlying SDLC task type (T1–T11), so none of the above findings can be decomposed by task type. Population is restricted to ≥500-star open-source repositories and five specific agents as of the AIDev snapshot; the authors themselves flag that findings "may not generalize to smaller projects, proprietary settings, or future agent systems" — directly limiting transfer to an enterprise/proprietary engineering context. **Can support:** nothing directly; recorded as a scope/generalisability caveat that should travel with every other finding from this source when cited.
