# peng-2023-copilot-rct — Original GitHub Copilot RCT (Upwork freelancers, HTTP-server task)

## Citation

Peng, S., Kalliamvakou, E., Cihon, P., & Demirer, M. (2023). *The Impact of AI on Developer Productivity: Evidence from GitHub Copilot.*

- arXiv: [2302.06590](https://arxiv.org/abs/2302.06590) — v1 only, submitted 13 Feb 2023, 18:42 UTC. cs.SE. DOI: 10.48550/arXiv.2302.06590. 9 pages + figures/appendix.
- Also indexed at: Microsoft Research publication page, Semantic Scholar (~145 citations tracked), ResearchGate (cites "417 citations" per a different tracker — trackers disagree substantially; treat citation counts as approximate).
- **Status: unpublished arXiv preprint. No peer-reviewed journal or conference venue found as of Jul 2026**, despite ~3.5 years' circulation and heavy citation. This is itself notable: one of the most-cited pieces of "evidence" in the AI-coding-productivity debate has never been peer-reviewed.

## Tier & era & independence

- **Tier: A, with a prominent COI flag.** Genuine RCT: random assignment to treatment/control, objective outcome (automated CI test-suite timestamps via GitHub Classroom, not self-report), pre-registered task and incentive structure, reported CI/p-value. Rigour is real. However: **3 of 4 authors are employees of the company that makes the product being tested** (Peng — Microsoft Research; Kalliamvakou & Cihon — GitHub Inc.), the study was run on GitHub/Microsoft's own product, and ethics review was performed by **Microsoft Research's own internal ethics board**, not an external/third-party IRB. The 4th author (Demirer, MIT Sloan) is the only non-vendor affiliation. There is no explicit conflict-of-interest disclosure section in the paper itself. Per CLAUDE.md's instruction that rigour and independence are graded separately: **Tier A (rigour) + explicit vendor-COI flag (independence)** — not downgraded to D, but never to be cited without the flag, and to be triangulated against independent replications before use in the exec brief.
- **Era: E1 (autocomplete era) — confirmed from the paper.** The tool studied is "GitHub Copilot, an AI pair programmer that suggests code and entire functions in real time based on context," powered by OpenAI Codex, run as a **pre-GA "technical preview"** (experiment window: 15 May–20 June 2022, ending "right before GitHub Copilot became generally available" — GA was 21 June 2022 per the companion Cui et al. paper). This is real-time inline/autocomplete suggestion only — no chat interface (Copilot Chat did not exist yet; ChatGPT itself launched 30 Nov 2022, after this experiment concluded). Unambiguously E1 by modality, not just by year.
- **Independence flags:**
  - 3/4 authors employed by the vendor whose product is being evaluated (GitHub/Microsoft).
  - Internal (Microsoft Research) ethics review, not an independent IRB.
  - Recruitment, task design, and incentive structure (pay scale explicitly rewarding speed: $160 for <30 min down to $20 for 150+ min) were set by the vendor via an Upwork job posting run by Microsoft.
  - No independent replication of this exact design (same task, same population type) was found.
  - Mitigating factor: outcome measurement itself is fully automated/objective (git timestamps + a fixed 12-test suite the participants could not alter), which limits (but does not eliminate — task framing, population, incentive design all remain vendor-controlled) the scope for measurement-side bias.

## Method & population

- **Design:** RCT. Experiment ran 15 May – 20 June 2022. 166 Upwork job offers sent; 95 accepted and randomised (45 treatment / 50 control) after signing an Upwork contract. Treatment group watched a 1-minute Copilot intro video and was given Copilot access; control group was unconstrained (could use internet search, Stack Overflow) but had no Copilot. Both groups completed an entry survey (demographics) and an exit survey.
- **Task (T3 — greenfield/prototyping):** Implement a toy HTTP server in JavaScript from a skeleton repo: parse a request string and return a response string (no real networking), serve files from a `content/` directory, handle only GET, return correct status codes (200/400/404/405) and a correctly formatted response with `Content-Length` header. Delivered via GitHub Classroom with a **fixed, visible-but-unmodifiable 12-test suite**. Single standardised task, ~1 hour expected duration (task advertised as "max time expected is around 1 hour"; actual completion times ranged much higher — see below).
- **Outcome measurement — MEASURED, not self-reported:** task completion time = elapsed time between automated repo-creation timestamp and the first commit/push that passed all 12 tests, both timestamps logged automatically by GitHub Classroom. Task success = binary pass/fail on the same test suite. This is a hard, objective, tamper-resistant measure — one of the strongest measurement designs in this literature.
- **Population:** freelance/contract developers recruited via Upwork, not employees of a single firm and not necessarily "professional" in a mature-org sense. Of screened/completed respondents (entry-survey n; note the entry-survey demographic charts in Fig. 5 sum to ~105, exceeding the 95 randomised — an unexplained inconsistency in the source paper, flagged here rather than resolved): modal age 25–34, majority from India and Pakistan, median yearly income $10,000–$19,999 (low by US standards), majority hold a 4-year degree or higher, average **6 years of professional coding experience**, average **9 hours/day spent coding** (i.e., heavy/full-time freelance coders, not casual moonlighters).
- **n completing the task + exit survey:** "Thirty-five developers from both the treated and control groups completed the task and survey" — read most consistently as **35 completers in each arm** (35/45 = 77.8% of treatment; 35/50 = 70.0% of control), which is the only reading that reproduces the paper's separately-stated "treated group's success rate is 7 percentage points higher than control" (77.8% − 70.0% = 7.8pp ≈ 7pp). **The primary 55.8% headline effect is therefore based on ~70 completers out of 95 randomised, not the full n=95.**

## Key findings

Task-type tag for all findings below: **T3 (greenfield/prototyping)** — a small, fully-specified, dependency-light task with no pre-existing codebase context.

1. **Headline effect (measured):** conditional on completing the task, mean completion time was **71.17 minutes (treatment) vs 160.89 minutes (control) — a 55.8% reduction**. t-test p = 0.0017. **95% CI for the improvement: [21%, 89%]** — a wide interval; the point estimate carries real uncertainty. Four outliers (>300 min), all in the control group; result is robust to dropping them. [T3; measured]
2. **Completion-rate difference (measured):** treatment group's task success rate was **7 percentage points higher** than control, but **not statistically significant**, 95% CI **[−11pp, +25pp]**. [T3; measured; null/non-significant result — recorded per CLAUDE.md rule 3]
3. **Heterogeneity (Table 1, Horvitz–Thompson-transformed regression of treatment effect on covariates):**
   - Programming experience (years): coefficient +8.23 (SE 4.36, p=0.063 — marginal)
   - Hours of programming per day: −11.70 (SE 4.74, p=0.017 — significant)
   - Age 25–44 (vs other ages): −74.55 (SE 33.52, p=0.030 — significant)
   - Unemployed: −35.98 (ns, p=0.33); Income <$20k: +0.64 (ns); No college: −36.57 (ns); Language pref. Java: −11.77 (ns); Python: +22.90 (ns)
   - **Authors' own interpretation of these coefficients: less experienced developers, developers with heavier daily coding loads, and older developers (25–44) benefit more from Copilot.** This is directly relevant to §5 tension 5 (seniority asymmetry) — direction consistent with "AI lifts the floor," reported here at the individual (not just job-tenure) level. [T3; measured; heterogeneity]
4. **Self-reported vs measured delta (both reported by source — recorded as its own finding per CLAUDE.md rule 4):** exit-survey self-estimated productivity gain averaged **~35%** across *both* treatment and control groups (control estimated after seeing a demo video) — an **underestimate** relative to the measured 55.8%. **Note the direction: here self-report underestimates the measured gain — the opposite direction from the METR (2025) perception gap, where self-report overestimated (and even inverted the sign of) the measured effect.** This divergence in direction is itself relevant to RQ2/RQ6 and should be flagged, not smoothed over, when synthesising perception-vs-reality evidence. [T3; self-reported, compared explicitly against measured]
5. **Revealed willingness-to-pay (secondary, measured via incentivized elicitation):** treated group's average stated maximum monthly price for Copilot access was $27.25 vs $16.91 for control, significant at 95%. Indirect evidence of perceived value, not a productivity measure per se. [T3; self-reported/elicited]
6. **Authors' own stated limitations (self-reported by the authors):** single standardised task, not representative of collaborative work on large proprietary/OSS codebases; results may not generalise across tasks/languages; **the study does not examine code quality effects at all** — the authors explicitly flag this as unexamined, not as a null result.

## What this can and cannot support

Tier-A-rigour (vendor-COI-flagged) evidence that, for a single short, fully-specified, no-context greenfield JavaScript task performed by freelance developers under time-pressure incentives, autocomplete-era Copilot produced a large and measured (not self-reported) reduction in completion time, with suggestive (not decisive — wide CIs, small n, one-tool one-task one-population) evidence that less-experienced/older/heavier-coding-load individuals benefited more. **It cannot support any claim about brownfield/mature-codebase work, chat- or agent-era tooling, code quality, team-level or organisational throughput, or professional (non-freelance) developer populations** — the authors themselves disclaim generalisation beyond the single task, and the era-transfer rule (PROTOCOL §2) blocks it from supporting any E3-level exec-brief claim on its own. Its primary current value is (a) a **baseline/historical anchor** for how large greenfield-task effects looked at the start of the AI-coding era, and (b) a **methodology exemplar** — the automated-timestamp/fixed-test-suite design is one of the cleanest "measured, not self-reported" outcome designs in the whole literature and is worth citing for that reason alone in RQ2 discussion.

## Corrections vs the seed description (PROTOCOL §6)

- Seed said "~55% faster… E1 autocomplete-era Copilot." **Confirmed accurate**, with the precise figure being **55.8%** (not a rounder ~55%), 95% CI [21%, 89%], p=0.0017 — and the era-tag is confirmed correct from the paper's own description of the tool (pre-GA technical preview, no chat).
- **Population correction:** the seed/task brief characterised the population loosely; precision added — these are **Upwork freelancers**, not in-house professional developers, average 6 years' experience, disproportionately India/Pakistan-based, working ~9 hours/day coding, under a pay structure that explicitly rewards speed. This is a materially different population from later workplace studies (Cui et al.) and should not be conflated with "professional developers" generically when this source is cited.
- **n correction:** the 55.8% figure is based on **~70 completers (35 per arm) out of 95 randomised (166 offered)**, not the full n=95 — completion itself was non-random-ish (7pp higher completion in treatment, though not significant). This matters for interpreting external validity: the headline number already conditions on who finished.
- **New finding not in the seed:** the self-report vs measured comparison in this paper runs in the *opposite direction* to the METR (2025) perception-reality gap (here self-report underestimates; METR self-report overestimates/inverts). This is a genuine contradiction-relevant nuance for RQ2/§5 tension 1 that the seed description did not anticipate.
- **Confirmed: no peer-reviewed venue exists.** The seed treated this as "the original Copilot RCT" without flagging its publication status; worth noting explicitly that this widely-cited paper remains an unrefereed preprint.

## Follow-up leads (for Phase 1 queue — not extracted here)

1. **Cui, K.Z., Demirer, M., Jaffe, S., Musolff, L., Peng, S., & Salz, T. (Feb 2025), "The Effects of Generative AI on High-Skilled Work: Evidence from Three Field Experiments with Software Developers."** SSRN 4945566; AEA RCT Registry AEARCTR-0014530. Real-workplace RCTs at Microsoft (n=1,521 analysed), Accenture (n=316), and an anonymous Fortune 100 company (n=3,030); pooled ~4,867 developers. Finds a **26.08% (SE 10.3%) increase in weekly completed pull requests** — and the authors **explicitly benchmark this against Peng et al. (2023)'s lab result**, calling it "substantially smaller than the [~58%, sic — actual figure is 55.8%] decrease Peng et al. (2023) find… It is perhaps unsurprising that the effect of the tool in real-world contexts is smaller than in the lab." Also replicates the seniority-asymmetry direction (short-tenure/junior developers gain more). **Highest-priority lead — this is the direct, same-research-team, greenfield-lab-vs-real-workplace contrast that PROTOCOL §5 tension 2 is built around.** Note: this is very likely the same underlying work the PROTOCOL §6 anchor list calls "Cui et al. (2024) — Copilot field experiments, Microsoft/Accenture" — the version found here is dated Feb 2025; **flag for that anchor's own verification pass to reconcile the year and confirm this is the canonical/latest version** (not a separate paper to double-extract). Not independent of Peng et al. — two authors (Demirer, Peng) are on both papers.
2. **Stray, V., Brandtzæg, E.G., Wivestad, V.T., Barbala, A., & Moe, N.B. (2026), "Developer Productivity With and Without GitHub Copilot: A Longitudinal Mixed-Methods Case Study."** HICSS-59 (2026) proceedings, pp. 7413–7422. https://hdl.handle.net/10125/112286 (CC BY-NC-ND). Independent team (University of Oslo / SINTEF, Norway), no Microsoft/GitHub affiliation. Real org (NAV IT, Norwegian public sector), 2-year longitudinal GitHub-activity dataset (26,317 commits, 703 repos, 25 Copilot users vs 14 non-users) + 13 interviews + survey. **Finds no statistically significant change in commit-based activity after Copilot adoption**, strong **self-selection effect** (Copilot adopters were already significantly more active before adoption — Mann-Whitney p<0.006), and a **perceived productivity increase with negligible correlation to any measured activity metric** (Spearman ρ≈0.17, p=0.41, not significant) — nearly all users reported "no change" or an increase even when their measured output fell. The paper explicitly cites and contrasts its null with Peng et al. (2023)'s 55.8%. **High-priority lead for §5 tension 1 (perception-reality) and tension 2 (lab vs real, greenfield vs real org).**
3. **arXiv 2506.10051**, "The Effects of GitHub Copilot on Computing Students' Programming Effectiveness, Efficiency, and Processes in Brownfield Programming Tasks" (2025) — direct greenfield-vs-brownfield contrast; population is students, not professionals — caveat if pursued.
4. **DevX Platform blog, "The 55% Productivity Myth: What GitHub Copilot's Research Really Tells Us"** (https://devxplatform.com/blog/the-55-percent-productivity-myth/) — practitioner critique specifically targeting over-generalisation of this paper's headline figure; useful for exec-brief expectation-setting language (Tier D — DevX is itself an analytics vendor, COI-flag if used).
5. **Nagle, F., Greenstein, S., Roche, M., Wright, N.L., & Mehta, S. (2023), "CoPilot(s): Generative AI at Microsoft and GitHub."** Harvard Business School Case 624-010 — background/origin-story case referenced by Cui et al.; not empirical, business-school teaching case only.
6. Multiple secondary/press write-ups (NN/g "AI Tools Make Programmers More Productive," Brookings labor-market piece, various vendor blogs) restate the 55.8% figure without new data — leads only, not sources to extract.

## Recency check notes

Source is **~3.5 years old** at verification (Feb 2023 → Jul 2026), well past the 12-month threshold. **Not retracted** — remains a single-version (v1) arXiv preprint, never revised, never published in a peer-reviewed venue. It has **not been superseded in the sense of being withdrawn or corrected**, but it has been substantially **recontextualised by its own co-authors' follow-up work**: Cui et al. (2025) — sharing two authors with this paper — found real-workplace effects roughly half the size (26% vs 55.8%) using the same vendor's product, and explicitly attributes the gap to lab-task vs real-job differences. An independent team (Stray et al., HICSS 2026) found no measurable effect at all in a different real-world org, alongside a self-selection confound this paper's design (random assignment) does not have but which matters for how its result should be read against observational follow-ups. Any future use of the 55.8% figure in synthesis must be paired with these two follow-ups and explicitly scoped to "single greenfield task, freelance population, pre-GA autocomplete Copilot" — it should not be quoted standalone as a general Copilot productivity effect.
