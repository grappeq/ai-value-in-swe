## Tier, era, independence

- **Tier: B.** Large-N (932k-PR parent dataset; working samples of 33,596 / 9,616 / 5,574 PRs), peer-reviewed (EASE 2026, ACM), with a validated measurement instrument (regex classifier, 96.5% accuracy against 800 manually-relabelled comments) and formal statistical testing (χ² with Benjamini–Hochberg FDR correction, Cramér's V effect sizes). **Not Tier A**: this is a cross-sectional descriptive/associational mining study with no causal identification strategy, no counterfactual, no time dimension, and no control for PR size/complexity/repo workflow — the authors themselves flag this as an unaddressed internal-validity threat. Sits alongside `churn-151-repos-2025`-class work in rigour of measurement, but without that source's causal design.
- **Era: E3, confirmed.** AI-generated PRs are drawn from AIDev's five agent tools — OpenAI Codex, Devin, GitHub Copilot (agent mode), Cursor, and Claude Code — genuinely autonomous multi-file authorship, not autocomplete or chat-panel copy-paste.
- **Independence — two distinct axes, pulling in opposite directions:**

## Dataset & method

- **Parent dataset:** AIDev — >932k pull requests with agentic/human authorship metadata, spanning five agent tools (per the cross-referenced AIDev paper: 932,791 agentic PRs, 116,211 repositories, 72,189 developers).
- **Working populations (after filtering):**
  - **𝑅ₚₒₚ** (repos with ≥1 agent-authored PR, restricted to ≥100 GitHub stars): **33,596 agent-authored PRs** — the RQ1 population; identical in size to AIDev's own pre-curated 100-star subset (see Independence above).
  - **𝑅∩ = 𝑅ₚₒₚ ∩ 𝑅ₕᵤₘₐₙ** (repos containing *both* agent- and human-authored PRs): **9,616 agent-authored PRs** and **5,574 human-authored PRs** — the RQ2 (comparison) population.
  - No exact calendar time period is stated anywhere in the visible text — a genuine gap; the analysis window is defined only by whatever AIDev's own snapshot covers, not independently dated by this paper.
- **Human-PR filtering (data-quality step, not a sampling design choice):** AIDev provides a stratified sample of human-authored PRs matched to AI-PR characteristics. The authors ran a two-step manual-verification cleaning pass and **removed 1,044 PRs from the human-authored set** that were actually bot/agent-authored (detected via "[bot]" username patterns and AI-tool keywords in PR bodies — e.g. "PR-Codex," "Copilot," "Claude," "Devin," "Cursor" — every match manually inspected). They also removed **588 misclassified human-authored comments from 𝐶(𝑃_AI) and 539 from 𝐶(𝑃_human)** — automated review mechanisms posing as ordinary "User" accounts (detected via username heuristics + ≥10-interaction threshold, manually verified).
- **Review-presence definition:** a PR counts as "reviewed" if and only if it has ≥1 recorded comment/review-discussion entry in its GitHub history (drawn from AIDev's bundled review records plus GitHub REST API calls for gaps). **The authors explicitly flag this as a known undercount mechanism**: *"The absence of review comments does not imply that the code was not reviewed (e.g., it may have received a silent approval). Nevertheless, we classify all PRs without comments as not reviewed, as there is no empirical basis to distinguish between these cases."* No use of a PR's "approved" state, no merge-event-based definition — purely comment/discussion presence.
- **Comment classifier (κ):** a validated rule-based regex classifier sorts every *human-authored* comment into exactly one of three categories — **agentic** (human steering an AI agent, e.g. "@coderabbit fix lint failure"; detected via agent-name + imperative-verb co-occurrence), **automation/CI** (chatops commands, bot-output markers, CLA/coverage notices), or **human_review** (the residual default class, deliberately merging substantive code critique with short procedural remarks like "lgtm"/"thanks"/pings — the authors tried separating these and abandoned it after finding "substantial lexical and functional overlap" and "unstable boundaries"). Validated on 800 manually re-labelled comments: **overall accuracy 96.5% (772/800)**; per-class precision/recall: Agentic 94.5%/95.0%, Automation 100%/96.6%, Human Review 95.8%/97.2%.
- **Statistics:** Pearson's χ² on contingency tables, Benjamini–Hochberg FDR correction across comparisons, conservative significance threshold p<0.001, effect sizes reported as Cramér's V.

## Key findings — exact numbers

### RQ1: AI-authored PRs in 𝑹ₚₒₚ (N=33,596; **no matched human-PR denominator in this population**)

- **No recorded review activity at all: 61.38% (20,621).**
- ≥1 review: 38.62% (12,975). Of these reviewed PRs:
  - Agent-only review: 58.77% (7,625)
  - Human-only review: 10.14% (1,316)
  - Mixed human+agent review: **31.09% (4,034)** per Table 1 — see internal-inconsistency note below (58.77+10.14+31.09 = 100.00, confirming 31.09% as the arithmetically correct figure).
- **Combined "no human involvement" framing: 84.0% (28,246/33,596)** of agent-authored PRs either receive no recorded review or are reviewed exclusively by other agents; **15.9% (5,350/33,596)** show some human participation.
- Comment level (39,122 total review comments on these PRs): **71.58% (28,004) agent-authored, 28.42% (11,118) human-authored.** Within human comments: human_review 64.53% (7,175), agent-steering 28.37% (3,154), automation 7.10% (789).

### RQ2: AI-authored vs human-authored PRs in 𝑹∩ — **this is the matched baseline**

- Review presence: AI PRs (N=9,616) — no review 28.92% (2,781), ≥1 review 71.08% (6,835). Human PRs (N=5,574) — no review 34.52% (1,924), ≥1 review 65.48% (3,650). **AI-authored PRs are reviewed slightly *more* often than human-authored PRs** (χ²(1)=51.44, p<10⁻³, V=0.06 — significant but small effect).
- **Observable human participation — the paper's central null result: 30.1% (2,896/9,616) for AI-authored PRs vs 30.8% (1,718/5,574) for human-authored PRs — "nearly identical."** Authorship type does not meaningfully predict whether a PR gets *any* observable human eyes on it, within the same repositories.
- Reviewer composition of reviewed PRs differs sharply, though: AI PRs — agent-only 57.63% (3,939), human-only 8.08% (552), mixed 34.29% (2,344); Human PRs — agent-only 52.93% (1,932), **human-only 25.21% (920)** — roughly **3× the AI-PR human-only rate** — mixed 21.86% (798). χ²(2)=629.4, p<10⁻³, V=0.25 (moderate).
- Comment-level composition: AI-PR comments 72.47% agent / 27.53% human; Human-PR comments 55.88% agent / 44.12% human. χ²(1)=873.7, p<10⁻³, V=0.16.
- **Strongest divergence — human-comment category, AI PRs vs Human PRs (χ²(3)=1280, p<10⁻³, V=0.34, the largest effect size in the paper):** for AI-authored PRs, human comments split 65.53% human_review / 25.92% agent-steering / 8.55% automation. For human-authored PRs: **93.56% human_review / 1.63% agent-steering / 4.81% automation.** When humans do engage with AI-authored code, a full quarter of that engagement is *directing the agent* rather than evaluating the output.

### Review depth (all settings)

Lightweight throughout: **2–3 comments per reviewed PR on average, std <3.5, in every configuration** — AI-Rpop 2.35±1.95 (agent comments) / 2.19±2.37 (human comments) per PR; AI-R∩ 2.66±2.16/2.19±2.46; Human-R∩ 2.05±1.66/2.57±3.32. No time-to-review, no approval-depth, no substantiveness measure beyond the three-way comment classifier.

### Repository breakdown

None. Only the ≥100-star cutoff is applied as a uniform filter; no subgroup analysis by repo size, domain, or popularity tier is reported.

## The comparison-baseline question, answered directly

**Yes, the paper supplies a matched human-authored baseline — but only for the 𝑅∩ subsample, not for the 𝑅ₚₒₚ population that produces the paper's most quotable headline number.** The 84.0%/61.38% figures (𝑅ₚₒₚ) have no same-denominator human-PR comparison; 𝑅ₚₒₚ is defined purely by containing ≥1 agent PR and is not matched against a same-repo human-PR set. Only 𝑅∩ carries the matched comparison, and there the story is materially less alarming than the unqualified 84% figure suggests in isolation: AI-authored and human-authored PRs receive observable human participation at statistically indistinguishable overall rates (30.1% vs 30.8%). **Anyone citing the 84%/61.38% figures without this caveat is presenting an unmatched-baseline statistic as if it were a comparative one** — a citation-hygiene risk worth flagging explicitly if this paper is quoted in synthesis or the exec brief.

## Nulls and negative results (recorded with equal diligence)

1. **Central null finding:** authorship type (AI vs human) does not predict the *presence* of observable human participation in the same repos (30.1% vs 30.8%, statistically indistinguishable in practical terms despite the large-N significance test elsewhere in the paper — note the authors do not report a significance test on this specific 30.1/30.8 comparison, only describe it as "nearly identical").
2. AI-authored PRs are reviewed *more*, not less, often than human-authored PRs at the raw presence level (71.08% vs 65.48%) — directly counter to a naive "AI code gets waved through unreviewed" story.
3. No defect, catch-rate, acceptance/dismissal, or quality-outcome measure is reported at all — the paper is explicit that it measures *review activity/structure*, not *review effectiveness*: "we report descriptive results and do not assess code quality or review effectiveness."

## Limitations (as stated by the authors)

- **Construct validity:** absence of comments ≠ absence of review (silent approvals are possible and explicitly acknowledged) but treated as "unreviewed" regardless, for lack of any way to distinguish the cases. This plausibly inflates *both* AI- and human-PR "no review" rates roughly symmetrically, so it likely does not bias the AI-vs-human comparison much, but it does mean the absolute levels (61.38%, 84.0%) should not be read as literal "nobody looked at this" rates.
- **Internal validity:** no control for PR size, complexity, or repo-specific workflow differences between AI-authored and human-authored PRs — an unaddressed confound the authors name themselves.
- **External validity:** GitHub/AIDev only, ≥100-star repos only. Explicitly: "results may not generalise to other settings." This is OSS, and specifically *relatively popular, active* OSS — not private/enterprise repos, and not low-visibility long-tail OSS either.
- **Conclusion validity:** purely descriptive; no code-quality or review-effectiveness assessment attempted.

## What this can and cannot support

**Can support:** an independent (authorship-wise), large-N, peer-reviewed, OSS cross-sectional confirmation of the *structural* half of tension 6 — that when review of AI-authored code happens, it is disproportionately automation-mediated (agent-only review, agent-steering commands) rather than substantive human evaluation, and that a meaningful share of nominal "human review activity" on AI-authored PRs is actually humans directing agents rather than assessing code. Can support a direct methodological warning (RQ2/RQ6-relevant): naive "did a human comment on this PR" metrics will over-count oversight in agentic workflows because they don't distinguish steering from evaluation. Can support, for the 𝑅∩ subsample specifically, that raw human-participation *rates* do not collapse for AI-authored code relative to human-authored code in the same OSS repos — a genuine, well-measured null result.

**Cannot support:** any claim about *trends over time* (no longitudinal dimension — this is a snapshot, unlike `he-2026-2x-mandate`'s 28-month panel); any claim about review *effectiveness*, defect catch-rate, or code quality (explicitly out of scope by the authors' own statement); any claim about enterprise/private-repo settings (OSS-only, ≥100-star-only); any causal attribution of the AI-vs-human differences observed (cross-sectional, uncontrolled for PR size/complexity); and — critically — the unqualified 84%/61.38% "no human involvement" headline cannot be read as a comparative claim against human-authored PRs, because no matched baseline exists for that specific population.

## Cross-ref assessment (for orchestrator review — synthesis/contradictions.md NOT edited)

**Overall verdict: a genuine independent (authorship-wise) leg for the *structural* half of tension 6, but a complicating, not confirming, data point for the *coverage-collapse* half — and not comparable to Faros's headline number at all.**

1. **vs. `he-2026-2x-mandate` (Tier A, single enterprise, 28-month DiD panel — the strongest quantified tension-6 source in this evidence base):** He et al. measure a **trend**: human review coverage fell 89%→68% as AI-authored PR volume surged inside one firm over time, driven mechanically by PR volume growing 3.1× against a reviewer pool growing only 1.5×. Duma et al. measure a **snapshot**: at one point in time, across many OSS repos, AI-authored and human-authored PRs receive observable human participation at statistically indistinguishable rates (30.1% vs 30.8%). **These are not directly comparable and do not contradict each other** — different design (panel vs cross-section), different population (one enterprise vs many OSS repos), different mechanism under test (coverage change over time vs authorship-type effect at a point in time). But read together they suggest a useful refinement: He et al.'s own explanation for the coverage collapse is a **capacity/volume story** (too much code overall, from any source, against fixed reviewer headcount), not a **discrimination story** (humans specifically deprioritising AI-authored code once they can tell what it is). Duma et al.'s finding — that OSS maintainers do not observably review AI-authored code *less* than human-authored code within the same repos — is consistent with, and lends some support to, reading He et al.'s bottleneck as volume-driven rather than authorship-discrimination-driven. Recommend synthesis present this as a **refining complement, not independent corroboration of the numeric coverage-drop trend** (which OSS cross-sectional data cannot speak to at all) **and not a contradiction either**.
   - Additional nuance for RQ2/measurement: He et al.'s "substantive human review" category (rest excludes silent-approval-only) is **not the same construct** as Duma et al.'s "human_review" comment category, which deliberately *includes* short procedural remarks like "lgtm" alongside substantive critique (the authors tried separating these and abandoned it for instability reasons). This means Duma's 64.53%/93.56% "human_review" shares likely include a good deal of what He et al. would classify as bare/silent-style engagement rather than substantive review. **Any synthesis pairing these two sources' review-quality percentages side by side would be comparing non-equivalent constructs** — flag this explicitly if both are cited together.
2. **vs. `faros-2026-whiplash` (Tier D, COI, +31.3% PRs merged without review):** **Not comparable, and should not be read as either corroborating or contradicting.** Faros's figure is a **within-team relative change** (percentage-point delta between a team's lowest- and highest-AI-adoption quarters) measured across a multi-company **enterprise** telemetry base where **agentic PR authorship is under 1%** — i.e. Faros is measuring what happens to review rates as teams adopt more AI-*assistance* for human-authored code, not what happens to autonomously agent-*authored* code specifically. Duma et al.'s figures are **absolute cross-sectional levels** of review presence for genuinely autonomous **agent-authored** PRs vs human-authored PRs, in **OSS**, at one snapshot. Different authorship construct (AI-assisted-human-authored vs autonomous-agent-authored), different population (enterprise vs OSS), different statistic type (relative delta vs absolute level). Superficially, Duma's "AI PRs reviewed slightly *more* often than human PRs" (71.08% vs 65.48%) sits in tension with Faros's "PRs merged without review rising as adoption rises" — but given the construct/population mismatch, **this should not be logged as a contradiction**; it is at most a flag that "AI-generated PR" means substantially different things across these two literatures, which is itself worth a line in the RQ2/taxonomy write-up.
3. **Does OSS data corroborate the enterprise pattern? Verdict: partially, and unevenly across the two halves of tension 6.** The **structural/qualitative** half (review of AI output looks different — more automation-mediated, more agent-only, more steering-not-evaluation) is corroborated by an independent research group using an independent (if dataset-overlapping-with-other-studies) large-N source. The **coverage-collapse** half (human oversight capacity is being displaced/overwhelmed) is **not tested** by this cross-sectional design and, on the one dimension it can speak to (does authorship type predict raw participation rate), the OSS evidence runs mildly counter to a naive version of that story rather than confirming it.
4. **Is this an independent leg for tension 6?** **Authorship-independent: yes** (distinct Polish academic group, no overlap with the CMU/Stanford cluster). **Dataset-independent: no** — see Independence section above; this source shares its entire empirical base with the AIDev dataset cluster already flagged in the ledger, and the RQ1 population is an exact match to AIDev's own pre-curated subset. Recommend counting this as one voice within the "AIDev cluster" for §3 triangulation purposes, not as a fully separate independent source, while still crediting the authorship-level independence for the specific *analytical claims and framing* (which are this group's own, not a re-report of AIDev's own paper).

## Notes on internal consistency

One discrepancy within the paper itself, flagged rather than silently resolved: **Table 1 reports the 𝑅ₚₒₚ "mixed human+AI" reviewer-composition share as 31.09% (4,034 of 12,975 reviewed PRs)**, which is arithmetically correct (58.77% + 10.14% + 31.09% = 100.00%). **The body text in §5.1 restates the identical count (4,034) as "40.34%"**, which is not arithmetically consistent with the other two components reported alongside it in the same sentence (58.77% + 10.14% + 40.34% = 109.25%). Both figures point to the same underlying count and the same substantive conclusion (mixed review is common), so this does not change the paper's findings, but 31.09% (the table figure) is the number that should be cited, not 40.34%. Recorded here because an earlier WebFetch-based extraction pass on this same paper reproduced the 40.34% error uncritically — a reminder that secondary/automated extraction passes on this paper specifically should be checked against Table 1 directly.
